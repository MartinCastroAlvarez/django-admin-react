### 2. Five-rules check (✅)
- No `ModelAdmin` parallel system introduced (no app code).
- No `Model.objects.all()` usage (no app code).
- No new write or delete paths.
- No CSRF/auth-affecting changes.
- Folder rule: `docs/screenshots/` is the only net-new folder.
  It is image-only and explained in `README.md`; the directory
  is self-describing and referenced by name. Optional follow-up:
  add a one-line `docs/screenshots/README.md` for full
  compliance with §5 (non-blocking, can land separately).

### 3. Playwright as developer-only dependency (✅)
This is the most architecturally sensitive decision in the PR.
Confirmed:
- `scripts/screenshots.mjs` invokes Playwright via a locally
  installed binary; the script is run on demand by a human/PM,
  not by CI and not by the package's runtime.
- No `package.json` at any level gains a `playwright` entry, so
  the published `pip`-installable package, the pnpm workspace
  install, and the CI install graph are all unchanged.
- This matches the "no new runtime dependency surface without
  Architect approval" rule. The dev-only screenshot tool is an
  acceptable Tier 1 use of `scripts/`.

### 4. Role-boundary respect (✅)
PM only mutated PM-owned or shared-doc files (`README.md`,
`PROGRESS.md`, `docs/pm-*.md`, `forum/REVIEW-pm-ux-*.md`,
`scripts/screenshots.*`, screenshot PNGs, `.gitignore`).
No other agent's durable state (Architect, Security folders)
was touched.
